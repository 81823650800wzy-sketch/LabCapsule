# LabCapsule V0.11.0 实体桌宠、AI 与 Claude 使用手册

本版采用“电脑负责理解与渲染、ESP32-S3 负责可靠显示和本地动作”的分工。设备的桌宠模式是独立界面，不会覆盖屏幕工作室、实验界面或壁纸；只有用户点击“在 COM8 打开桌宠界面”后才会启用。

## 一、安装与固件更新

1. 下载 `LabCapsule-Studio-0.11.0.exe` 和 `LabCapsule-0.11.0-ota.bin`，并核对 `release/README.md` 中的 SHA-256。
2. 首次升级到 V0.11 建议用 USB 完整烧录，避免旧固件不认识桌宠协议：

   ```powershell
   . 'D:\Espressif\frameworks\esp-idf-v5.5.4\export.ps1'
   cd <仓库目录>\firmware
   idf.py build
   idf.py -p COM8 flash
   ```

3. 烧录不会格式化 8 MiB 数据/媒体分区；本次真机升级后原有 3 组离线实验和当前壁纸仍存在。
4. 运行 EXE。程序只打开所选 USB 串口，不切换电脑 Wi-Fi，也不连接设备的无网络恢复热点。

## 二、连接 COM8

1. 在顶部“数据线设备”选择 `COM8 — USB-Enhanced-SERIAL CH343 (COM8)`。
2. 点击“连接”，等待约 5–15 秒。ESP32-S3 复位期间第一次命令可能丢失，程序会每 2 秒自动重试握手。
3. “状态中心”应出现：

   ```text
   PONG,LABCAPSULE,0.11.0-alpha
   STATUS,READY,MPU=OK,MOCK=OFF,SAMPLES=0,RATE=200,DURATION=10
   ```

4. V0.11 最终固件会在 `STATUS` 握手阶段透明重试尚未稳定的 MPU6050，普通使用无需手工处理。只有排障时才进入“诊断日志”发送 `SENSORS`；正确结果为 `COUNT=1,MPU=OK,ADDRESS=0x68`。

## 三、打开实体桌宠独立界面

1. 进入“AI 桌宠”。连接设备本身不会自动切换屏幕。
2. 点击“在 COM8 打开桌宠界面”。按钮变灰表示已经启用。
3. 屏幕上半部显示本地绘制的胶囊角色，下方固定 `216 × 64` 单色中文对话框；角色动作由固件本地持续播放，电脑不发送屏幕视频。
4. 点击“退出设备桌宠界面”可返回普通设备状态页。
5. 诊断命令 `PET,STATUS` 可查看：

   ```text
   PET,VIEW=ON,EMOTION=HAPPY,ACTION=TALK,BUBBLE=YES
   ```

支持的动作被限制为 `IDLE / BOUNCE / TILT / THINK / TALK / SCAN / CELEBRATE / ALERT / SLEEP`。任意模型输出不能生成其他设备命令。

## 四、配置在线 AI

1. 在“角色与 AI 设置”填写 OpenAI 兼容 Endpoint、模型和 API Key。
2. DeepSeek 当前推荐配置：

   ```text
   Endpoint: https://api.deepseek.com/v1
   Model: deepseek-v4-flash
   ```

3. 旧配置中的 `deepseek-chat` / `deepseek-reasoner` 在官方 DeepSeek Endpoint 下会自动迁移到 `deepseek-v4-flash`；自建兼容服务的模型名不会被改写。
4. API Key 使用当前 Windows 用户的 DPAPI 加密，不写入仓库、日志、设备或对话气泡。
5. 不填 Key 时仍可使用本地规则回答连接、状态和实验摘要，但不会进行开放式联网推理。

DeepSeek 当前模型、更新和 Chat Completion 参数以官方文档为准：

- <https://api-docs.deepseek.com/quick_start/pricing/>
- <https://api-docs.deepseek.com/updates/>
- <https://api-docs.deepseek.com/api/create-chat-completion/>

## 五、电脑与实验问答

快捷按钮采用 2×2 布局：

- “电脑状态”：回答 CPU、内存、磁盘、运行时间、电源与电池信息。
- “解释当前状态”：同时读取 COM 端口、固件、实验状态、采样率、时长、样本数和电脑摘要。
- “设计一个实验”：生成运动/振动实验方案；复杂问题可转交 Claude。
- “检查数据质量”：结合最近六轴样本与统计摘要检查异常。

用户发送的每条正常回答在实体桌宠模式启用时都会同步；`device_notice` 只限制自动事件，不再意外阻止用户主动问答。电脑先把回答渲染为固定 1728 字节位图，再用 CRC32 上传，ESP32 不承担中文字体排版或大模型负载。

气泡链路使用 64 字节分片和明确节流，并在固件端设置 3 秒接收超时。传输中断会自动退出上传状态，避免下一条 `HOST` 命令被误当成二进制尾部。

## 六、复杂任务转交本机 Claude

勾选“复杂任务自动转交本机 Claude（只读安全模式）”后，包含多阶段设计、详细 FFT 分析计划、方案比较等复杂请求会调用已安装且已登录的 Claude Code CLI。简单电脑状态和设备状态仍由主 API 直接回答。

Claude 子流程采用以下边界：

- 禁用全部工具、浏览器、MCP、Slash Command 和会话持久化；
- `dontAsk` 权限模式、单轮、低 effort、0.20 美元预算上限；
- 不能启动/停止实验，不能更新固件、修改网络或读写用户文件；
- 工具调用 XML/内部标记会被拒绝，必要时自动进行一次无工具重试；
- 完整回答显示在电脑端，设备只接收经过脱敏和截断的短气泡。

Claude CLI 选项以 Anthropic 官方说明为准：<https://docs.anthropic.com/en/docs/claude-code/cli-usage>。

## 七、Live2D 角色

1. 点击“统一桌宠管理”，选择包含 `*.model3.json` 的模型文件夹或其父级角色库。
2. 首次运行必须由素材权利人确认 Live2D/Cubism 条款；LabCapsule 不随 EXE 分发 Cubism Core 或第三方 Hiyori 文件。
3. 模型通过 moc3、PNG 纹理、物理、姿态、动作和路径边界检查后，点击“打开 Live2D 舞台”。底部必须显示 `WebGL 就绪`。
4. AI 的安全动作会写入一个原子本地控制文件，由舞台每 300 ms 读取并映射到模型已有动作组；例如 `BOUNCE` 优先映射 `FlickUp`。
5. ESP32-S3 不直接运行 moc3。实体屏仍使用轻量本地角色和中文气泡，以保证实验采样与显示稳定。

用户提供的 Hiyori Pro 已在本版实测识别 2 张纹理、10 个动作，并完成 `Flick` 与 `HAPPY + BOUNCE → FlickUp` 动态测试。模型留在用户原目录，不进入仓库或 Release。

## 八、手机端路线

V0.11 先完成电脑端。Android V0.7 仍可继续完成 BLE 配网、实验、数据、媒体和 OTA，但尚未包含本版完整 AI 桌宠页面。固件已经提供可复用的 `PET` 状态/动作与固定气泡协议；后续手机端将复用相同的动作白名单、位图尺寸、CRC 和安全确认规则，不在 ESP32 上增加第二套模型逻辑。

## 九、排障

- 屏幕无变化：确认先点击“在 COM8 打开桌宠界面”，再发送 `PET,STATUS`。
- `BUBBLE=NO`：等待当前回答完成；若仍失败，查看是否出现 `ERR,UPLOAD`。
- 上传中断：V0.11 固件 3 秒后自动回到文本命令模式，可重新发送。
- AI 报错：检查 Endpoint、模型、Key 和电脑外网；不要让电脑连接 LabCapsule 恢复热点。
- Claude 不可用：先在终端运行 `claude --version` 并完成官方登录；主 AI 与本地回退不受影响。
- Live2D 空白：确认底部状态、WebView2、模型依赖和授权；不要关闭 CSP 或使用来源不明的 Core。

完整角色包制作规范继续见 [V0.10.0 统一桌宠手册](V0.10.0_UNIFIED_PET_PACKAGE_TEST_ZH.md)，网络形象见 [V0.9.0 指南](V0.9.0_NETWORK_AVATAR_GUIDE_ZH.md)。
