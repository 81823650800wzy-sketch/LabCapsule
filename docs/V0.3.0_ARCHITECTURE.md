# LabCapsule V0.3.0 架构说明

## 目标与边界

V0.3.0 把 LabCapsule 从单一 MPU6050 原型扩展为可持续加入传感器、可在正常互联网环境中使用、可通过 Wi-Fi/BLE 更新和传输媒体的实体小组件。当前实验主线仍限定为运动/振动；麦克风、GPS、NFC、电池和环境传感器仅通过扩展接口预留，不冒充已经完成的硬件功能。

## 分层

```text
Android 应用
├─ 中文 UI / 液态导航 / 页面动效
├─ AI 协议生成与本地回退
├─ 图片与 GIF 解码、RGB565 转换
├─ GitHub Release 更新检查
└─ HTTP / BLE 传输
        ↓
ESP32-S3 连接层
├─ Wi-Fi AP+STA + HTTP API
├─ MQTT/mqtts 出站远程通道
├─ BLE GATT 控制/状态/OTA/媒体
└─ 双 OTA 槽与 CRC 校验
        ↓
设备核心
├─ 实验状态机 / USB 串口数据流
├─ Sensor Hub 驱动注册表
├─ ST7789 双缓冲渲染
└─ NVS 配置 / 双槽持久壁纸
```

## 为什么采用 AP+STA

恢复热点只负责首次配置和救援，Station 同时连接外部路由器。手机在设置完成后切回原有 Wi-Fi，仍可通过设备的 `staIp` 控制，并继续使用互联网和 AI。保留恢复热点是默认策略；若部署环境要求减少射频暴露，可以关闭，但应确认 Station 连通后再操作。

## 局域网与远程

- 局域网：APK 直接调用设备 HTTP API，延迟低，适合图片、GIF 帧和 OTA。
- 远程：设备作为 MQTT 客户端主动建立出站连接，适合跨 NAT 的状态和命令；部署者可以使用成熟 Broker、ACL 和自动化平台。
- V0.3.0 不包含厂商云账号、云端媒体存储或 HTTP 反向隧道。跨公网图片应由可信后端转为局域网/BLE 媒体链路，固件不会从不可信 URL 自行下载内容。

## 显示刷新和媒体生命周期

UI 先在 PSRAM 后台帧缓冲完整绘制。呈现时不发送“全屏清黑”，而是把每 8 行复制到内部 DMA 缓冲后覆盖屏幕。这样避免大块 PSRAM 触发 SPI 私有缓冲分配失败，也避免清屏与新内容之间的黑闪。

静态壁纸在专用 Flash 分区中持久化；临时图片和 GIF 当前帧只存在 PSRAM。GIF 文件、帧时间轴和解码都在 Android 端，ESP32 不保存原文件。

## 传感器插件契约

每个驱动声明：

- 稳定 ID 与名称；
- 总线种类、I²C 地址或端口标识；
- 能力字符串；
- `probe`、`start`、`sample_json` 回调。

扩展顺序建议：驱动探测 → 单传感器采样测试 → 注册 Sensor Hub → 在 Experiment Protocol 增加能力映射 → APK 根据 `/api/sensors` 动态展示。SPI/UART/ADC/OneWire 需要在硬件设计中另外冻结引脚和电气要求。

## 安全与可靠性

- Android Keystore AES/GCM 保存 API Key、Wi-Fi 和 MQTT 密码。
- 网络配置通过 JSON 请求体发送，状态响应脱敏。
- MQTT 远程建议只用 `mqtts://`、每设备账号和最小主题 ACL。
- OTA 在备用分区写入，校验通过后才切换启动分区。
- BLE 媒体以长度和 CRC32 验证；未完成传输不会显示/提交。
- 本地 HTTP 当前依赖恢复热点 WPA 和受信任 LAN，不应直接暴露到公网。

## 后续兼容方向

1. 为 HTTP API 增加首次配对生成的设备令牌。
2. 增加 mDNS/局域网自动发现，减少手工填写 `staIp`。
3. 建立经过认证的云端 MQTT/WebSocket 网关，使 APK 直接查看远程状态。
4. 将 Experiment Protocol 和采集结果以版本化 schema 管理。
5. 增加独立渲染任务、帧率自适应和 GIF 丢帧策略。
