# LabCapsule V0.3.1 中文使用指南

V0.3.1 的重点是把图片/GIF 的重处理移到 Android 手机，并让外部 Wi-Fi 连接结果直接显示在 APK 中。ESP32 负责接收已经裁剪、量化和压缩的像素区域以及稳定刷新屏幕。

## 1. 安装与版本确认

安装 `release/LabCapsule-0.3.1.apk`。固件从 V0.3.0 升级可使用 APK 的 Wi-Fi/BLE OTA；首次安装或从旧分区表升级必须用 USB 完整烧录。

串口启动成功时会看到：

```text
BOOT,LABCAPSULE,0.3.1-alpha
OK,DISPLAY,ST7789,...
OK,CONNECTIVITY,WIFI=192.168.4.1,BLE=READY
```

## 2. 不让手机长期停留在无网络热点

1. 首次配置时，手机临时连接 `LabCapsule-XXXX`，密码 `labcapsule`。
2. APK 的“设备”页地址保持 `http://192.168.4.1`，点击“检测设备”。
3. 到“设置”填写实验室或家庭的 2.4 GHz Wi-Fi SSID/密码，保存。
4. 返回“设备”，APK 会自动轮询，也可以点击“刷新 Wi-Fi 状态”。
5. 显示绿色“已连接外部 Wi-Fi”且出现 `局域网 IP：http://...` 后，点击“使用此局域网 IP”。
6. 手机切回正常联网 Wi-Fi；只要手机和 LabCapsule 在同一局域网，屏幕控制、媒体和 OTA 都继续可用，同时手机仍能访问 AI 服务。

状态卡有三种结果：

- “尚未配置”：`staConfigured=false`，需要先保存 SSID。
- “已保存配置，正在连接或连接失败”：`staConfigured=true`、`staConnected=false`，常见原因是使用了 5 GHz 专用 SSID、密码错误或信号弱。
- “已连接外部 Wi-Fi”：`staConnected=true` 且 `staIp` 有效，APK 会显示完整 HTTP 地址并提供一键使用按钮。

设备热点是首次配置与救援通道。不要让运行 Codex 或需要持续联网的电脑切换到这个无互联网热点；用手机配置，或直接使用 BLE。

## 3. 上传图片前裁剪

1. 打开“屏幕”，点击“选择并裁剪”。
2. 选取 JPG、PNG 或 WebP。
3. 在编辑器内单指拖动、双指缩放，让目标内容进入白色 3:4 框。
4. 点击“确认裁剪”。APK 此时才生成设备所需的 240×320 画面；原始图片不会上传。
5. 点击“显示图片”进行临时显示，或点击“保存壁纸”写入设备壁纸分区。

临时静态图在手机端比较 RGB565 原始数据与 RLE565，自动选择更小者。壁纸为了持久存储和完整画质，仍使用固定 153,600 字节 RGB565。

## 4. GIF 流式播放

GIF 也必须先确认同一个 3:4 裁剪区域。播放期间手机承担：

1. 解码当前时间点的 GIF 帧；
2. 按裁剪框缩放成 240×320；
3. 量化为 RGB332，使首帧最坏从旧版 153,600 字节降为 76,800 字节；
4. 与上一帧比较，只截取发生变化的最小矩形；
5. 对矩形尝试 RLE332，并在 RLE 没有收益时回退到原始 RGB332；
6. 完全未变化的帧直接跳过，不占用链路。

Wi-Fi 播放以约 125 ms 为一步，BLE 以约 350 ms 为一步，而且 BLE 只在上一帧 GATT 传输完成后生成下一帧，避免队列堆积。ESP32 不保存 GIF 原文件，也不负责 GIF 解码，只把收到的局部像素同步写入两张 PSRAM 帧缓冲并覆盖显示。

“媒体工作台”会显示本帧编码、变化区域、有效字节和相对旧版 153,600 字节整帧的节省比例。运动范围越小、纯色越多，压缩效果越明显。

## 5. 通道选择

- 局域网 Wi-Fi：适合 GIF、壁纸和 OTA；设备接入外部路由器后，手机无需绑定恢复热点。
- BLE：适合控制、救援、图片以及低帧率 GIF；大文件会比局域网慢，但不占用手机 Wi-Fi。
- USB 串口：适合开发诊断和实验原始数据，不承担 APK 媒体传输。

## 6. 故障定位

- 找不到局域网 IP：查看状态卡是否为橙色，确认路由器提供 2.4 GHz、SSID/密码正确；必要时让手机回到恢复热点重新保存。
- GIF 卡顿：优先局域网；缩小动画变化范围、降低源 GIF 复杂度。V0.3.1 已自动差分和限速，不需要把 GIF 放进 ESP32。
- 图片内容不合适：点击“重新裁剪”，不必重新选择文件。
- 屏幕无变化：进入设备页确认在线，再用“彩条测试”；同时检查 ST7789 的 3V3、GND、GPIO12/11/10/7/6/5。
- MPU6050：当前 COM8 实物在 I²C `0x68` 有响应，但读到 `WHO_AM_I=0x70`；正式实验前应核对实际模块型号与接线。
