# LabCapsule V0.5.0 离线实验与硬件扩展指南

本版本的目标是让 LabCapsule 不依赖手机热点也能完成实验：有实时接收端时直接上传，没有接收端时写入设备内部缓存，之后再由 APK 同步和分析。

## 1. 先理解 5 GHz 限制

ESP32-S3 的 Wi-Fi 仅支持 2.4 GHz，不支持纯 5 GHz SSID。因此在只有 5 GHz 的环境中：

- `staConnected=false` 与 `staIp=0.0.0.0` 是预期状态；
- 手机和电脑继续使用原来的有互联网网络，不要连接 LabCapsule 无互联网热点；
- APK 仍可通过 BLE 完成控制、I²C 扫描、状态读取、图片/壁纸、OTA、实时实验和离线数据同步；
- 将来有 2.4 GHz、双频路由器或开启 2.4 GHz 兼容模式的手机热点后，再配置外部 Wi-Fi 即可。

## 2. 首次升级必须完整烧录

V0.5.0 新增 8 MiB `offline` 分区。只烧 OTA 应用镜像不会创建新分区，因此从旧版本升级时要通过 USB 完整烧录一次：

```powershell
. 'D:\Espressif\frameworks\esp-idf-v5.5.4\export.ps1'
cd <仓库目录>\firmware
idf.py build
idf.py -p COM8 flash
```

不要运行 `erase-flash`，除非确实希望清除 Wi-Fi/MQTT 设置、壁纸和所有离线实验。完成一次完整烧录后，后续同分区版本可恢复使用 APK OTA。

## 3. 只使用设备硬件完成实验

当前六按键行为：

| 状态 | 按键 | 动作 |
|---|---|---|
| 主页 | LEFT / RIGHT | 降低 / 提高采样率 |
| 主页 | DOWN / UP | 缩短 / 延长实验时长 |
| 主页 | OK | 开始实验 |
| 主页 | BACK | 进入设置 |
| 采集中 | OK | 正常停止并完成会话 |
| 采集中 | BACK | 中止并标记会话 |

未连接 APK、BLE 或 MQTT 时，六轴样本自动写入离线分区。主页显示 `LOCAL n RUNS` 表示已有离线会话；正在缓存时显示 `CACHE n LIVE`。USB 串口即使没有程序读取也不会再阻塞采样。

## 4. 在线直传与离线缓存的判定

每条样本独立判断：

```text
BLE 实验数据通知已订阅并接受该样本？ ── 是 ──→ BLE 实时上传
                │ 否
MQTT 数据队列已连接并接受该样本？       ── 是 ──→ MQTT 实时上传
                │ 否
                └──────────────────────→ 写入离线 LCB1 会话
```

因此实验中途断线后，后续没有成功直传的样本仍会进入缓存。完全在线且 200 条均成功通知的实验不会额外产生离线文件，减少 Flash 写入。

## 5. 在 APK 中同步设备缓存

1. 保持 BLE 已连接；纯 5 GHz 环境不影响此步骤。
2. 打开 APK“数据”页。
3. 在“设备离线缓存”点击“读取状态”，确认会话数、样本数和容量。
4. 点击“同步并分析”。APK 通过 BLE `0008` 特征分片读取；若设备与手机在同一 2.4 GHz 局域网，也可通过 `/api/offline` 下载。
5. APK 将首个会话转换为私有 CSV，随后计算 RMS、Peak、FFT 和主频。
6. 确认同步文件有效后，再点击“清空设备缓存”。清空不可撤销，不建议在同步前操作。

同步文件位于 APK 私有目录 `experiment-sync/`，BLE 实时实验 CSV 位于 `live-experiments/`。卸载 APK 会删除这些私有文件，重要数据应先分享或另行备份。

## 6. 增加摇杆或其他操作硬件

固件通过 `firmware/main/input_hub.h` 隔离物理输入与界面行为。新输入驱动只需要周期返回动作位图：

```c
static input_action_mask_t joystick_poll(void *context)
{
    input_action_mask_t actions = 0;
    /* 读取 ADC、GPIO、I/O 扩展器或按键矩阵。 */
    if (x_axis < low_threshold)  actions |= INPUT_ACTION_BIT(INPUT_ACTION_LEFT);
    if (x_axis > high_threshold) actions |= INPUT_ACTION_BIT(INPUT_ACTION_RIGHT);
    if (y_axis < low_threshold)  actions |= INPUT_ACTION_BIT(INPUT_ACTION_UP);
    if (y_axis > high_threshold) actions |= INPUT_ACTION_BIT(INPUT_ACTION_DOWN);
    if (pressed)                 actions |= INPUT_ACTION_BIT(INPUT_ACTION_OK);
    return actions;
}
```

然后在初始化阶段注册：

```c
const input_driver_t joystick = {
    .id = "analog-joystick",
    .poll = joystick_poll,
    .context = &joystick_config,
    .debounce_ms = 45,
};
ESP_ERROR_CHECK(input_hub_register(&joystick));
```

最多可注册 8 个输入来源。现有 `gpio-buttons` 已占一个。新增模拟摇杆前必须先确定未占用且支持 ADC 的引脚；不要直接复用屏幕 SPI、I²C、USB 或当前六按键引脚。具体引脚应在最终硬件原理图冻结后配置，不能仅凭软件猜测。

## 7. 增加传感器

`firmware/main/sensor_hub.h` 的 `sensor_driver_t` 预留 I²C、SPI、UART、ADC 和 OneWire：

1. 为传感器实现 `probe`、`start` 和 `sample_json` 回调。
2. 填写稳定的 `id`、显示名称、总线、地址和能力字符串。
3. 在初始化阶段调用 `sensor_hub_register()`。
4. 通过 APK BLE `SENSORS` 或 HTTP `/api/sensors` 验证发现结果。
5. 若要把新传感器写入实验文件，应为 `LCB1` 增加新的格式版本或独立记录类型，不能改变 V1 固定 16 字节样本而不升级版本号。

当前 I²C 使用 SDA GPIO8、SCL GPIO9、3.3 V 和共地。总线扫描只能证明地址有应答，不能证明芯片型号完全正确；当前实机的 `0x68` 返回 `WHO_AM_I=0x70`，接入正式实验前仍需核对模块。

## 8. 开发验证工具

仓库提供两个不会切换电脑 Wi-Fi 的 BLE 测试：

```powershell
cd <仓库目录>
python tools\ble_offline_smoke.py --scan-timeout 20
python tools\ble_live_smoke.py --scan-timeout 20 --rate 100 --duration 2
```

第一个读取摘要、导出并逐个校验 `LCB1` 会话；第二个统计在线通知，并确认完全在线实验不会新增离线文件。

## 9. 当前实机基准

2026-08-28 在 COM8 的 ESP32-S3 rev 0.2 / 16 MiB Flash / 8 MiB PSRAM 上验证：

- 离线 Mock：100 Hz × 2 秒，串口 200 条、缓存 200 条、丢样 0；
- BLE 在线 Mock：通知 200/200，离线会话数保持不变；
- BLE 离线导出：3 个会话、507 条样本、8,208 字节，全部头和长度校验通过；
- APK 0.5.0：Android API 26–35 编译通过，APK Signature Scheme v2/v3 验证通过。
