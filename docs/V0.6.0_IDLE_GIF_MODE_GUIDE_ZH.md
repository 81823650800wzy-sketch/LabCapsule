# LabCapsule V0.6.0 工作模式、通知与 GIF 指南

> 历史版本说明：V0.7 已用设备本地 LCG 动画和 1–8 FPS 取代本页的手机后台逐帧播放与百分比调速。当前操作请优先阅读 [V0.7.0 本地媒体与桌面工作室指南](V0.7.0_LOCAL_MEDIA_DESKTOP_GUIDE_ZH.md)。

本指南对应固件 `0.6.0-alpha` 和 Android APK `0.6.0`。本次升级不要求手机连接 LabCapsule 的无网络热点；已有 5 GHz 网络且没有 2.4 GHz 时，请继续使用 BLE。

## 1. 更新顺序

1. 用 USB-C 保持设备连接电脑，确认端口为 `USB-Enhanced-SERIAL CH343 (COM8)`。
2. 固件可通过 COM8 完整烧录，也可从 0.5.0 使用 APK 选择 `LabCapsule-0.6.0-ota.bin` 更新。
3. 安装 `LabCapsule-0.6.0.apk`。这是开发签名包；Android 会要求确认安装来源。
4. 打开 APK，进入“设置 → 设备与连接”，展开后扫描并连接 `LabCapsule-XXXX`。
5. 不要让电脑连接设备恢复热点。该热点没有互联网，会中断正在使用的在线开发工具。

## 2. 两种工作模式

### 闲置信息模式

1. 在首页“设备工作模式”点击“闲置信息”。
2. 输入最多约 16 个字符的标题和 32 个字符的摘要。当前设备字体支持英文、数字、空格及 `- . :`；APK 会安全简化其他字符。
3. 确认后，屏幕进入 `IDLE DASH`，每秒更新：
   - 运行时间；
   - 内部 RAM 与 PSRAM 使用情况；
   - 离线实验存储占用及会话数；
   - BLE、外部 Wi-Fi Station 和 MQTT/远程状态；
   - 当前通知摘要。
4. APK 首页或“设置 → 设备与连接”点击“刷新负载/刷新硬件使用情况”，可查看更精确的百分比和连接状态。

### 实验直传模式

1. 点击“实验直传”，或直接从首页、实验页、AI 页启动实验。
2. BLE 实验数据特征已订阅或 MQTT 队列成功接收时，样本立即发送给手机、电脑或服务器。
3. 没有在线接收端时，设备把样本写入 8 MiB 离线分区；连接恢复后在“数据 → 设备离线缓存 → 同步并分析”导出。
4. 物理按钮/未来摇杆仍走同一个输入中心，因此没有手机也能设置和开始实验。

## 3. 手机通知镜像

1. 在“闲置信息”对话框勾选“同步后续手机通知到闲置屏幕”，或在折叠的设备设置中开启“闲置时镜像手机系统通知”。
2. Android 将打开“通知使用权”。手动允许“LabCapsule 手机通知镜像”。这是 Android 的强制安全步骤，APK 不会静默开启。
3. 返回 APK，保持设备工作模式为闲置。之后新的通知摘要会经当前所选通道发送：
   - BLE：使用上次成功连接的设备地址，按需短连接；
   - 局域网：向已保存设备地址的 `/api/mode` 发送摘要。
4. 若不希望正文出现在设备上，开启“通知隐私模式（只显示应用名）”。
5. 以下情况自动暂停镜像：设备为实验模式、GIF 正在后台播放、用户关闭开关。这样不会抢占实验样本或动态壁纸链路。

## 4. GIF 速度调整

1. 展开“设置 → 屏幕、壁纸与 GIF”。
2. 用“GIF 播放速度”滑杆选择 `25%–300%`：
   - `100%`：使用 APK 预处理后的基准时间轴；
   - 小于 `100%`：慢放；
   - 大于 `100%`：加速，可补偿部分链路等待。
3. 如果 GIF 已在播放，松开滑杆后速度立即传给后台服务，无需重新裁剪或重新启动。
4. 速度设置会持久保存，退出 APK 后仍有效。系统“强行停止”应用会终止后台服务。
5. 当一帧的实际传输时间已经超过目标间隔时，提高百分比不能突破 BLE/Wi-Fi 物理带宽。优先选择变化区域较小、颜色较少的 GIF，或使用局域网通道。

## 5. 自由裁剪与缩放

1. 点击“选择并裁剪”，选取 JPG、PNG、WebP 或 GIF。
2. 白色 3:4 框代表设备 240×320 屏幕：
   - 单指拖动图片；
   - 双指围绕触点缩放；
   - 使用下方 `100%–800%` 滑杆精确缩放；
   - 点击“复位”恢复完整覆盖裁剪框的最小比例。
3. 确认后，APK 才会把裁剪区域缩放到 240×320。GIF 的抽帧、RGB332 量化和差分编码全部在手机完成，ESP32 不保存 GIF。

## 6. 连接状态判断

- `staConnected=true` 且 `staIp` 不是 `0.0.0.0`：设备已接入外部 2.4 GHz Wi-Fi，可使用局域网地址。
- `staConnected=false`、`staIp=0.0.0.0`：外部 Wi-Fi 未连接。纯 5 GHz 网络属于预期失败，因为 ESP32-S3 只支持 2.4 GHz。
- 只有 5 GHz 时：选择 BLE，仍可切换模式、读取硬件、扫描 I²C、传图片、更新固件、运行实验和同步离线数据。
- 恢复热点找不到时：通过 BLE 点击“恢复设备热点”；无需让手机或电脑长期加入该热点。

## 7. PC/串口命令

串口为 460800 baud：

```text
MODE,IDLE
NOTICE,PC LINK,BUILD COMPLETE
MODE,EXPERIMENT
STATUS
```

BLE 对应命令：

```text
MODE:IDLE
NOTICE:PHONE LINK|READY FOR NOTICES
MODE:EXPERIMENT
HARDWARE
```

HTTP 模式接口：

```json
POST /api/mode
{"mode":"idle","title":"PHONE LINK","message":"READY FOR NOTICES"}
```

## 8. 当前硬件提醒

本次 COM8 真机测试中，I²C 地址 `0x68` 有应答，但 `WHO_AM_I=0x70` 与标准 MPU6050 的常见标识不一致，并且真实传感器在设置 100 Hz 时被拒绝。BLE 实时链路因此使用临时 Mock 数据验证，完成后已恢复 `MOCK,OFF`。正式实验前请确认模块型号、供电、GPIO8/9 接线和焊点，不要把 Mock 验证结果当作真实运动数据。
