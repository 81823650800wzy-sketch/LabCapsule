# LabCapsule V0.7.0 本地媒体与桌面工作室指南

本指南对应固件 `0.7.0-alpha`、Android APK `0.7.0` 和 Windows `LabCapsule Studio 0.7.0`。全流程优先使用 BLE 或 USB，不要求手机、电脑连接 LabCapsule 的无互联网恢复热点。

## 1. 推荐更新顺序

1. 用数据 USB-C 连接设备，Windows 设备管理器应显示 `USB-Enhanced-SERIAL CH343 (COM8)`。
2. 在 `firmware` 目录执行 `idf.py -p COM8 flash`。V0.5/0.6 已使用同一分区表，也可通过 APK 安装 `LabCapsule-0.7.0-ota.bin`。
3. 安装 `LabCapsule-0.7.0.apk`。Android 会要求确认安装来源，这是系统安全要求。
4. Windows 可直接运行 `LabCapsule-Studio-0.7.0.exe`；源码运行见 `desktop/README.md`。
5. 不要把电脑切换到 `LabCapsule-XXXX` 热点。桌面工作室只走数据线，不影响电脑现有互联网连接。

## 2. 初始颜色

V0.7 启动值为 `INVERT=OFF`。可在串口执行：

```text
DISPLAY,DEV
```

应看到 `INVERT=OFF`。如果具体屏幕模组确实需要反色，可在 APK/桌面端点击“颜色反转”，或执行 `DISPLAY,INVERT`；该操作不再作为默认值。

## 3. 当前媒体存储规则

设备只保留一个当前媒体：

- 静态图片：高质量 RGB565，存入独立壁纸分区；
- GIF/视频/桌宠动画：手机或电脑生成 LCG4，存入 `/offline/current.lcg`，最大 6 MiB；
- 保存新静态图片会删除旧动画；保存新动画会清除旧壁纸有效标记；
- 动画上传先写 8.3 临时文件 `currtmp.lcg`，校验 CRC、帧边界、尺寸和编码后原子替换；
- 手机退出、被系统回收、屏幕熄灭或设备重启后，动画仍由 ESP32 自主播放。

动画不是原始 GIF 文件。手机/电脑先完成 240×320 裁剪、抽帧、RGB332 量化、变化框检测以及 RGB/RLE/稀疏 delta 三选一压缩，因此显著降低 Flash、BLE 和解码负担。

## 4. APK 图片与 GIF

1. 进入“设置”，展开“屏幕、壁纸与 GIF”。
2. 点击“选择并裁剪”。裁剪框固定为屏幕 3:4 比例。
3. 缩放范围为 `25%–800%`：小于 `100%` 时图像可完整缩小到框内，空白由“黑色补底”或“白色补底”填充。
4. GIF 速度直接选择 `1–8 FPS`。8 FPS 是当前 ST7789 10 MHz 稳定整屏链路的参考上限，不使用百分比。
5. 点击“保存壁纸”写入静态图片；点击“上传并播放 GIF”会先在手机预处理，再通过 BLE 或局域网一次上传。
6. 上传完成后可以退出 APK。重新进入后刷新设备状态，首页会显示当前媒体、播放状态和 FPS。

高变化、长时间视频可能超过 6 MiB。降低 FPS、缩短素材或使用较小的变化区域；设备不会用实时后台传输来掩盖超限。

## 5. Windows 桌面工作室

双击 EXE，或运行：

```powershell
cd <仓库目录>\desktop
.\run.ps1
```

### 状态中心

- 端口列表优先选择 COM8；连接后自动 `PING` 和 `STATUS`。
- 每 2 秒把 CPU、内存、系统盘使用率和可用温度发送给设备；未进行实验时设备自动显示电脑硬件仪表。
- 点击“启用系统通知读取”后，Windows 会请求通知访问。新 Toast 的标题与摘要会发送到闲置屏；未授权时仍可手动发送测试通知。

### 屏幕工作室

- 预览框严格为 240×320。
- 支持 PNG/JPG/WebP/BMP/GIF/MP4/AVI/MOV/MKV/WebM。
- 支持适应/填充、黑白补底、0.25–8 倍缩放、水平/垂直平移。
- 可叠加透明 PNG/WebP/GIF 桌宠，并调整 X、Y 和缩放。
- 静态图片以 RGB565 写壁纸；GIF、视频和桌宠动画以 LCG4 写当前动画。
- 主页、设置、开发、色卡、背光、反色以及壁纸/面板/HUD 透明度可直接操作。

### 实验与数据

- 设置 10–500 Hz、1–3600 秒，选择真实 MPU 或 Mock 后开始。
- 实时解析 `DATA,timestamp,AX,AY,AZ,GX,GY,GZ`，绘制加速度模长趋势。
- 停止或完成后导出带 UTF-8 BOM 的 CSV，可继续使用仓库分析模块计算 RMS、Peak、FFT 和主频。

## 6. USB 媒体协议

桌面端发送：

```text
UPLOAD,CLIP,1674,C0B56A4A
```

设备返回 `READY,UPLOAD,CLIP,BYTES=1674` 后，客户端发送恰好 1674 字节原始数据。成功返回：

```text
OK,UPLOAD,CLIP,CRC=C0B56A4A
OK,GIF,PLAY,FPS=4,BYTES=1674
```

静态壁纸对应 `UPLOAD,WALLPAPER,153600,CRC32`。CRC 或容器失败返回 `ERR,UPLOAD`，不会启用损坏动画。

其他串口命令：

```text
HOST,23,47,61,-1
GIF,FPS,8
GIF,PLAY
GIF,STOP
GIF,DELETE
MODE,IDLE
MODE,EXPERIMENT
NOTICE,PC LINK,BUILD COMPLETE
```

## 7. 性能边界

- 当前实机 SPI 为 10 MHz，整屏可靠上限按 8 FPS 暴露；局部 delta 帧通常更轻，但 UI 不承诺超过实机整屏能力。
- ESP32 不解码 JPG、GIF 或 H.264；复杂格式全部由手机/电脑处理。
- 设备媒体上限 6 MiB，为 8 MiB 离线分区保留文件系统和实验数据余量。
- MP4 桌面解码依赖 FFmpeg，已包含在发布 EXE；源码运行由 `imageio-ffmpeg` 提供。

## 8. 本次实机验收

2026-08-28，COM8 / ESP32-S3 rev 0.2 / 16 MiB Flash / 8 MiB Octal PSRAM：

- 固件构建通过，应用镜像约 1.39 MiB，3 MiB OTA 槽剩余约 56%；
- 串口返回 `PONG,LABCAPSULE,0.7.0-alpha` 和 `INVERT=OFF`；
- 1674 B / 3 帧测试动画完成 USB READY、CRC、原子替换和自主播放；
- 4 FPS 为 250 ms，运行中改 8 FPS 后为 125 ms；
- 设备重启后测试动画自动播放；
- 测试动画删除后，测试前备份的原壁纸分区已完整恢复并返回 `OK,DISPLAY,WALLPAPER`；
- APK v2/v3 签名验证、桌面 UI 启动、静态图/GIF/MP4 编码均通过。

ESP32-S3 仍只支持 2.4 GHz Wi-Fi。只有 5 GHz 时使用 BLE 或 USB；`staConnected=false`、`staIp=0.0.0.0` 属于硬件能力边界，不影响本指南中的 USB 功能。
