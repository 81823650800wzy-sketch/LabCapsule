# LabCapsule V0.8.0 交互图表与 AI 桌宠设计

本版本先完成 Windows 电脑端，继续兼容 V0.7 固件和 Android APK。它解决两个实际问题：实验曲线必须能被精确检查，而桌宠必须理解设备与实验，不能只是循环播放的一张透明图片。

参考项目：[Project AIRI](https://github.com/moeru-ai/airi) / [AIRI 文档](https://airi.moeru.ai/docs/)。LabCapsule 借鉴 AIRI 对“角色、Agent 核心、桌面舞台、渲染与外部集成”的分层思路，但没有复制其代码，也没有在当前阶段引入 Electron、VRM、Live2D 或完整插件体系。V0.8 选择更适合本设备的轻量 Python/Tk 桌面运行时，优先保证 USB 实验链路、低资源占用和明确的安全边界。

## 一、交互式实验数据

### 通道和坐标

图表保留设备上送的原始微秒时间戳和全部六轴值，并在电脑端计算 `|A|`、`|G|`：

| 通道 | 含义 | 单位 |
|---|---|---|
| AX / AY / AZ | 三轴加速度 | g |
| GX / GY / GZ | 三轴角速度 | °/s |
| \|A\| | 加速度矢量模长 | g |
| \|G\| | 角速度矢量模长 | °/s |

鼠标靠近曲线时，十字线吸附到最近的真实样本，而不是对绘图线段做视觉估算。读数同时包含实验相对时间、设备原始 `timestamp_us`、通道、Y 值和单位。多个通道重叠时，选择与鼠标纵坐标最近的已启用通道。加速度 `g` 与角速度 `°/s` 使用独立 Y 轴和独立自动范围，避免不同量级互相压扁；只显示一类单位时统一使用左轴。

### 缩放和平移

- 普通滚轮：以鼠标所在位置为锚点缩放 X 时间轴。
- `Ctrl + 滚轮`：以鼠标所在位置为锚点缩放 Y 数值轴。
- 左键拖动：同时平移 X/Y；进入手动检查模式后暂停自动跟随。
- 双击或“复位视图”：恢复实时跟随和 Y 轴自动范围。
- 时间窗口：2、5、10、30、60 秒或全部。
- 通道开关只改变画面，不改变内存中的原始点和 CSV 导出。

### 性能分配

- 接收和保存原始样本，最多保留 100,000 点用于当前会话查看。
- 图表重绘请求合并到约 30 FPS；不会为每个 100/500 Hz 样本都完整刷新一次窗口。
- 曲线按画布横向像素分桶抽稀，每桶保留局部最小值和最大值，减少 Tk Canvas 负载的同时不漏掉窄脉冲峰值。
- AI 上下文只读取最近最多 5,000 点的最小值、最大值、RMS、末值、时长和估计采样率，不发送整份 CSV。
- CSV 导出仍使用完整 `samples` 数据，不受绘图抽稀影响。

## 二、AI 桌宠不是“贴图模式”

### 电脑端分层

```text
USB Serial / 实验事件 / 用户消息
                ↓
       有界 Device Context
                ↓
  Pet Agent Runtime + Local Memory
       ↓                    ↓
安全结构化回复          本地规则回退
       ↓
角色状态机 / 对话 / 桌面悬浮层
       ↓
可选短通知同步到 LabCapsule 屏幕
```

1. **角色配置**：名称、人格和欢迎语与模型配置分离，后续可由电脑和 Android 共享。
2. **感知上下文**：只包含设备是否连接、端口、设备状态、是否采样、样本数、最新样本、图表选择和有界运动统计。
3. **Agent 运行时**：调用 OpenAI 兼容 `/chat/completions`，要求返回 `reply/emotion/device_notice/memory_fact` JSON；默认兼容 DeepSeek，也可换成本地或其他兼容服务。
4. **本地回退**：没有 Key 或网络失败时仍能解释连接状态、提醒实验步骤并响应连接/完成/错误事件。
5. **角色状态机**：`idle/happy/curious/thinking/speaking/experiment/success/warning/sleeping` 驱动颜色、表情、字幕和悬浮宠物。
6. **设备桥接**：只在非采样阶段向 240×320 屏幕发送安全的短 ASCII 通知，避免字体限制和实时采样争用。

### 当前交互体验

- 角色眼睛会跟随鼠标并随机眨眼，不需要 GIF 或持续向设备传帧。
- 主窗口提供角色舞台、聊天、快捷问题和设置；悬浮层始终置顶、可拖动、双击返回 AI 页、右键隐藏。
- 连接、断开、实验开始、实验完成、中止和设备错误都可触发本地即时反应，不为每个事件调用一次付费模型。
- “解释当前状态”和“检查数据质量”会把结构化运动统计交给模型，不会把几十万原始点塞入请求。
- 回复可以提出实验建议，但不能假装已经执行操作。

### 隐私与安全

| 数据/动作 | 处理方式 |
|---|---|
| API Key | Windows DPAPI 按当前用户加密，配置 JSON 中不保存明文 |
| 最近对话 | 本机最多 40 条，可关闭、可一键清除 |
| 长期偏好 | 最多 20 条、每条 160 字；过滤 Key/密码/token/secret |
| 屏幕和文件 | V0.8 不采集、不提供给模型 |
| 查看状态、生成说明 | 被动动作，可直接执行 |
| 屏幕短通知 | 用户显式打开同步后执行，采样时自动暂停 |
| 开始/停止/中止实验 | 必须由用户点击确认，模型没有直接工具 |
| 修改 Wi-Fi、烧录/OTA | 必须进入专用设置流程确认，模型没有直接工具 |

Endpoint 会被拼接为 `/chat/completions`。公网 Endpoint 强制使用 HTTPS，只有 `localhost/127.0.0.1/::1` 可使用 HTTP，以便接入本地模型。第三方服务会看到发出的对话和设备摘要；持久化消息还会对常见 Key、token、secret 和密码格式做本地脱敏。

## 三、面向 Android 双端的协议设计

V0.8 提供 [Pet Event V1 JSON Schema](pet_event_v1.schema.json)。后续 Android 不重写一套互不兼容的桌宠逻辑，而是共享以下对象：

- `CharacterProfile`：角色 ID、名称、人格版本和视觉主题。
- `PetEvent`：来源、会话、事件类型、上下文、情绪、动作建议和风险级别。
- `DeviceSnapshot`：连接、传感器、实验、媒体和有界统计，不传 API Key。
- `ActionProposal`：AI 只能提出动作；客户端根据 `passive/confirm/blocked` 决定是否显示确认页。

双端阶段按以下顺序实施：

1. Android 先实现同一 `pet_event_v1` 编解码、角色状态和本地事件反应。
2. 通过 BLE 或局域网同步角色状态、短消息和设备快照；大图/动画继续走既有媒体传输，不塞进事件 JSON。
3. 每次设备会话只有一个“主动 Agent 租约”：电脑在 USB 活跃时优先，电脑断开后手机才接管，防止双端重复回复和重复下发。
4. 所有动作带唯一事件 ID；设备和客户端保存短期去重表，重连后重复消息不会再次执行。
5. API Key 各端分别使用 DPAPI/Android Keystore 保存，绝不经 BLE、局域网或设备转发。
6. 角色偏好同步采用显式开关和字段白名单；原始聊天默认不跨端同步。

这条路线让“电脑桌宠”和“手机桌宠”是同一角色的两个舞台，而不是两个同时争抢设备的机器人。

## 四、当前限制与下一阶段

- V0.8 角色为原创轻量矢量胶囊形象，还不是 VRM/Live2D。以后可增加 renderer port，再接 2D 骨骼或 3D 模型，不改变 Agent 与设备桥。
- 当前记忆是本地有界 JSON，不包含向量检索；应在有明确删除、导出和加密方案后再扩展长期记忆。
- 当前 AI 读取摘要但不直接做 FFT 结论。后续应复用实验分析模块，把可复核的 RMS/Peak/FFT 结果作为结构化工具结果交给 Agent。
- Windows 通知镜像仍是用户主动授权的独立能力，不自动成为桌宠模型输入。
- V0.8 不改变 ESP32-S3 仅支持 2.4 GHz Wi-Fi 的硬件限制；纯 5 GHz 环境继续使用 USB/BLE 或增加双频路由/AP。
