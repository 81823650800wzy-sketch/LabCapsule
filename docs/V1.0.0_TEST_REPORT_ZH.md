# LabCapsule V1.0.0 测试报告

测试日期：2026-09-01。电脑为 Windows 11 / Python 3.12 / ESP-IDF 5.5.4；实体为 COM8 的 ESP32-S3 rev0.2、16 MiB Flash、8 MiB Octal PSRAM、ST7789 240×320、I²C 0x68 运动传感器。

## COM8 实机

完整烧录写入 bootloader、OTA app、partition table 和初始 OTA data，全部哈希校验通过，未执行 `erase-flash`。重启后的只读验收为：

```text
PONG,LABCAPSULE,1.0.0-alpha,DEVICE=lc-000000000000
IDENTITY,...CHARACTER=live2d-000000000000,PROXY=ON,...MIC_PORT
STATUS,READY,MPU=OK,MOCK=OFF,SAMPLES=0,RATE=200,DURATION=10
NETWORK,..."staConnected":false,"staIp":"0.0.0.0"...
SENSORS,COUNT=1,MPU=OK,ADDRESS=0x68,RESULT=ESP_OK
PET,VIEW=ON,...CHARACTER=live2d-000000000000,PROXY=ON
```

当前只有 5 GHz 网络，故未让电脑加入设备恢复热点，也未宣称 STA 成功。USB、BLE、屏幕和传感器不受影响。

## BLE 实机

Windows Bleak 扫描并连接 `LabCapsule-6625` 成功。状态 JSON 可完整解析，返回：

- 固件 `1.0.0-alpha`；
- 设备 `lc-000000000000`；
- Hiyori `live2d-000000000000`；
- `staConnected=false`、`staIp=0.0.0.0`；
- 传感器 count 1、MPU6050 0x68。

中文实体气泡和动作命令在上一轮实机链路验证成功；V1 状态压缩后未再发生 BLE JSON 截断。

## Hiyori

实际模型：`<Live2D模型目录>\hiyori_free\runtime\hiyori_free_t08.model3.json`。模型内容哈希生成 `live2d-000000000000`；识别到 8 组动作。Windows 已保存为默认 Hiyori Free。24 帧、8 FPS、240×320 设备代理已写入 COM8，重启后仍由设备本地播放。

模型受原许可约束，不提交仓库或打进二进制。Android 运行时导入在本轮完成构建和静态校验；当前 ADB 未发现手机，因此未把“Android 真机 WebView 成功渲染”标为已验证。

## 已知边界

- ESP32-S3 无 5 GHz 射频；纯 5 GHz 下 STA 不可能连接。
- 实体板当前没有麦克风；V1 提供 PC 录音转写、Android 系统语音入口和 `MIC_PORT` 扩展契约。
- GitHub 记忆同步必须使用用户自己的私有仓库和最小权限 Token；本轮未使用真实 Token 执行远端写入测试。
- APK 使用开发签名，EXE 未使用商业代码签名；对外发行前必须换正式证书。
- Live2D 首次渲染依赖官方 Cubism Core 和用户许可确认。
