# LabCapsule V1.0 统一随身实验助手使用指南

> 本文中的 `lc-000000000000`、`live2d-000000000000` 和本地目录均为公开版合成示例；使用时以应用显示的本机值为准。

V1.0 把 ESP32-S3 设备、Windows Studio 和 Android APK 统一为同一个 Hiyori 实验助手。设备负责稳定采样、离线保存和 240×320 显示；电脑或手机负责 Live2D、AI、语音、媒体预处理、详细图表和私有记忆同步。这样既不会要求 ESP32-S3 运行超出其能力的模型，也不会依赖手机在后台逐帧传 GIF。

本版的稳定身份是硬件派生的 `deviceId`。本次 COM8 实机为：

```text
deviceId    = lc-000000000000
characterId = live2d-000000000000
model       = Hiyori Free
```

COM 号、局域网 IP 和手机名称都可能变化，不能代替 `deviceId`。

## 一、三分钟快速开始

### Windows

1. 保持电脑连接自己的有网络 Wi-Fi，不要加入 `LabCapsule-XXXX` 恢复热点。
2. 用数据 USB-C 连接设备，运行 `LabCapsule-Studio-1.0.0.exe`。
3. 在“实验助手”顶部选择“USB 串口”和 COM8，然后连接。
4. 确认身份卡显示 `lc-000000000000`，设备屏幕保持独立 Hiyori 页面。
5. 在“设置 → AI 与记忆”填入 OpenAI 兼容 Endpoint、模型和 API Key；Key 由当前 Windows 用户的 DPAPI 加密。
6. 输入问题或点击“说话 6 秒”。Hiyori 的回答显示在电脑端，同时以底部气泡和动作同步到实体屏。
7. 在“实验数据”选择采样率和时长并开始；实时曲线可悬停读数、滚轮缩放、拖动平移，结束后自动保存 CSV 和会话摘要。

### Android

1. 安装 `LabCapsule-1.0.0.apk`，允许“附近设备”；需要语音时再允许麦克风。
2. 进入“设置 → 设备与连接”，优先用 BLE 扫描 `LabCapsule-6625`。BLE 不会占用手机 Wi-Fi。
3. 身份卡必须显示设备 `lc-000000000000`、角色 `live2d-000000000000`。
4. 进入“AI”，点击“选择现有 Live2D 文件夹”，选择手机里包含 `model3.json`、moc3、纹理和动作的完整 `hiyori_free` 文件夹。模型只复制到 APK 私有目录，不上传仓库。
5. 填入 AI Endpoint、模型和 Key，之后可打字、使用 Android 系统语音识别或让 AI 解读最近实验。
6. “实验”负责协议和采集，“数据”负责离线会话、CSV、RMS、Peak、FFT；设备、屏幕、固件、网络和记忆都放在“设置”并默认折叠。

## 二、使用现有 Hiyori，不创建新形象

Windows 本次已使用：

```text
<Live2D模型目录>\hiyori_free\runtime\hiyori_free_t08.model3.json
```

Studio 会校验 model3、moc3、纹理、动作、Physics/Pose 引用，随后从模型 JSON 内容生成稳定角色 ID。本机选择已经保存；以后启动会重新校验并自动恢复 Hiyori Free。旧版 `local-*` 选择会自动迁移，不再因为电脑路径不同而变成另一个角色。

Android 无法直接读取电脑的 `D:` 盘。先把完整 `hiyori_free` 文件夹复制到手机，再在 APK 中选择文件夹。APK 最多导入 800 个文件、128 MiB，递归深度最多 12；导入采用临时目录验证后原子切换，不完整的新模型不会覆盖旧模型。

Live2D 模型不进入本仓库、APK、EXE 或 GitHub Release。应用只携带开源播放器代码；Cubism Core 在用户确认适用条款后从 Live2D 官方地址加载。离线时实体屏仍显示已经写入设备的同角色代理动画，但手机/电脑首次启动 Live2D 需要可访问 Core。

### 实体屏为何不是直接运行 moc3

ESP32-S3 不运行 Cubism WebGL。Windows/Android 从同一个 Hiyori 模型触发动作，Windows 可把 240×320、最高 8 FPS 的预渲染代理一次性写入设备。设备只保存当前壁纸或当前动画，并在本地循环播放，所以退出 APK、手机锁屏或断开连接后动画不会停止。

## 三、连接方式

| 连接 | 推荐用途 | 是否影响手机/电脑上网 | 大文件 |
|---|---|---|---|
| USB 460800 | 首次烧录、稳定实验、桌面使用 | 否 | 最佳 |
| BLE | 配网、控制、状态、实验、离线同步、气泡和压缩媒体 | 否 | 可用，较慢 |
| 局域网 HTTP | 已连同一路由器后的控制和媒体 | 否 | 良好 |
| MQTT/mqtts | 设备主动外连的远程状态/命令 | 否 | 不用于大媒体 |

### 外部 Wi-Fi

ESP32-S3 只支持 2.4 GHz Wi-Fi。纯 5 GHz 路由器下的正确状态就是：

```text
staConnected=false
staIp=0.0.0.0
```

这不会影响 USB、BLE、硬件按键、传感器扫描、实体屏、本地 GIF 和离线实验。需要局域网连接时，请在双频路由器开启 2.4 GHz、使用手机 2.4 GHz 热点，或增加一个 2.4 GHz AP。APK 的“蓝牙一键配网”只把 SSID/密码发给设备，手机本身始终留在有互联网的网络。

恢复热点 `LabCapsule-XXXX` 只用于 BLE 不可用时排障；Codex/电脑工作期间不要连接它，以免电脑掉线。

## 四、统一记忆库

记忆不是放在 ESP32 中，而由连接端按稳定 `deviceId` 读取和合并。这样设备换电脑、换手机后仍定位到同一份记忆，同时避免把 GitHub Token 和 API Key 放入硬件。

1. 在 GitHub 创建一个私有仓库，例如 `your-name/labcapsule-memory`。
2. 创建只允许该仓库 Contents 读写的细粒度 Token。
3. Windows 或 Android 的“设置 → AI 与记忆”填写仓库、分支和 Token，启用同步。
4. 第一次连接设备后点击同步。文件路径为：

   ```text
   memory/devices/lc-000000000000/snapshot.json
   ```

5. 另一台电脑或手机连接同一硬件并使用同一私有仓库后，会拉取、去重合并、增加 revision，再安全回写。

同步最多保存 80 条脱敏事实和 20 个实验会话摘要。API Key、Token、密码、Wi-Fi 凭据、原始音频不会进入记忆。应用拒绝向公开仓库写记忆；Token 分别由 Windows DPAPI 和 Android Keystore 加密。

## 五、AI、语音、动作和 Claude

### AI 服务

Windows 和 Android 都使用 OpenAI 兼容的聊天接口，可填写 DeepSeek 或其他兼容服务。回答必须经过结构化白名单：

```json
{
  "reply": "给用户看的简体中文回答",
  "emotion": "CURIOUS",
  "action": "SCAN",
  "memory_fact": "可选的长期偏好"
}
```

动作只允许 `IDLE/BOUNCE/TILT/THINK/TALK/SCAN/CELEBRATE/ALERT/SLEEP`。AI 不能绕过按钮直接刷固件、修改 Wi-Fi、清空数据或擅自开始/中止实验。

### 语音

- Windows：使用系统默认麦克风录制 16 kHz 单声道 WAV，再发送到配置的 OpenAI 兼容 `/audio/transcriptions`。原始音频不写入记忆库。
- Android：调用系统语音识别界面；应用本身不常驻监听。
- 实体硬件：固件已经声明 `MIC_PORT` 扩展能力，但当前冻结硬件表没有麦克风。后续加入 I²S 麦克风时，由连接的电脑或手机做 VAD、转写和 AI 推理，ESP32 只传输有界音频块和显示结果。

### 复杂任务

Windows 可启用“复杂任务自动转交本机 Claude”。桥接固定为单轮只读、禁用工具/MCP/浏览器、无会话持久化且有超时预算；如果本机没有 Claude，会继续使用主 AI，不会阻塞实验。Android V1 不远程唤起电脑上的 Claude。

## 六、实验和双端数据

实体按键无需手机或电脑也能运行实验：

- 左/右：调整采样率；
- 上/下：调整时长；
- OK：开始或正常停止；
- BACK：中止。

有 BLE 订阅或 MQTT 接收端时，样本实时上传；没有接收端时写入 8 MiB 离线分区。稍后 Android 可同步离线会话，Windows USB 可直接保存实时 CSV。

Windows 曲线包含 AX/AY/AZ、GX/GY/GZ、加速度合量和角速度合量。鼠标悬停读取时间和数值，滚轮缩放时间轴，`Ctrl + 滚轮` 缩放 Y 轴，左键拖动，双击复位。显示抽稀不改变原始 CSV。

AI 回答实验问题时只接收精简上下文：设备身份、连接健康、传感器扫描、当前实验、统计摘要和最多 12 条记忆。组件资料通过仓库 Skill 按需检索，不把整个仓库塞入一次请求，也不把 Mock 数据描述为真实测量。

## 七、传感器与操作硬件扩展

固件 `sensor_hub` 支持最多 16 个驱动，预留 I²C、SPI、UART、ADC、OneWire；当前注册 MPU6050，发现表覆盖 BME/BMP280、SHT3x、INA219、ADS1115、VL53L0X。新增元件步骤：

1. 实现独立 probe/start/read 回调；
2. 填写总线、地址和 capabilities；
3. 在启动时调用 `sensor_hub_register()`；
4. 在 `knowledge/catalog.json` 增加小型组件说明；
5. 用 `skills/labcapsule-context-access` 查询并验证只加载相关资料。

`input_hub` 把六按键、未来摇杆、矩阵键盘、I/O 扩展器和远程虚拟按键统一为逻辑动作。新输入驱动只需返回动作位图，不复制实验状态机。

## 八、媒体、GIF 和屏幕

图片、GIF 和视频先在手机/电脑完成裁剪、缩放、补黑/白底、量化、抽帧与差分压缩；ESP32 只做校验、持久化、解码和 DMA 绘制。

- 裁剪缩放：25%–800%，可缩小到画面以内并补底；
- GIF 速度：1–8 FPS，单位是真实帧率，不是百分比；
- 存储：只保留当前壁纸或当前 LCG 动画；
- 刷新：PSRAM 双缓冲与局部 DMA 覆盖，不先清黑屏；
- 屏幕监看：应用按 240×320 比例展示设备状态和页面，不通过 BLE 持续拉取整块帧缓冲。

## 九、升级与恢复

- 首次安装或分区表变化：使用 USB 执行完整 `idf.py -p COM8 flash`。
- 普通更新：APK 可从 GitHub Releases 检查 APK 和 OTA bin；Android 安装确认由系统完成。
- 不要运行 `erase-flash`，否则会删除 Wi-Fi/NVS、当前角色身份、壁纸/动画和离线实验。
- OTA 失败时保留当前可启动分区；媒体采用临时文件、CRC32 和原子替换。

## 十、常见问题

**角色不统一**：确认三端 `characterId` 都是 `live2d-000000000000`。Windows 重新选择 `hiyori_free` 父文件夹；Android 重新导入同一 Free 文件夹；再上传一次设备代理。

**Android Live2D 空白**：确认导入的是完整文件夹且手机能访问 Live2D 官方 Cubism Core。模型文件不完整、Core 被网络拦截或 WebView 过旧都会失败；实体屏代理不受影响。

**STA 一直 false**：确认网络确实提供 2.4 GHz。只有 5 GHz 时不要重复改密码，直接用 BLE/USB。

**GIF 退出 APK 后停止**：确认使用的是“上传为设备本地 GIF/动画”，不是旧版临时逐帧预览。状态中应显示 `gifPlaying=true` 和真实 FPS。

**传感器扫描为 0**：先看 `STATUS` 的 `MPU=OK`，再执行 `SENSORS`。V1 已修复活动 MPU 驱动与扩展探测争用；本次 COM8 返回 `COUNT=1`、地址 `0x68`。

**屏幕无响应**：打开开发诊断页，核对 ST7789 GPIO12/11/10/7/6/5、3.3 V 和共地；ST7789 为只写 SPI，软件无法回读面板物理状态。

## 十一、当前发布边界

V1.0 已完成开发签名 APK、单文件 Windows EXE、ESP-IDF 固件和 COM8/BLE 实机回归。若作为对外销售产品，还需完成正式 Android 签名和商店流程、代码签名证书、设备外壳与 EMC/射频/电气合规、HTTP 局域网认证、生产密钥注入、崩溃上报隐私政策以及 Live2D/Cubism 商用许可复核。
