# LabCapsule V1.3.0 AI 真实实验使用指南

V1.3 把“对话”和“真正开始实验”连接成一条可检查的安全链。APK 不再仅靠关键词生成固定协议：在线 AI 会分析用户目标，并明确给出传感器、采样率、时长、分析方法，以及是否需要电脑 Claude 推理或联网查找参考资料。任何参数未通过本地校验、传感器未实际在线或设备拒绝 START 时，实验都不会被标记为已开始。

## 一、首次配置

1. 安装 `LabCapsule-1.3.0.apk`，打开“设置 → AI 服务”。
2. 填写 OpenAI 兼容 Endpoint、模型名和 API Key。默认 DeepSeek Endpoint 为 `https://api.deepseek.com/chat/completions`；Key 只保存在 Android Keystore，不发送到 ESP32 或仓库。
3. 在“设置 → 设备与连接”连接 BLE，或先检测已在同一局域网的设备。只有 5 GHz Wi-Fi 时直接使用 BLE；不要把手机切到设备的无网络恢复热点。
4. 点击“扫描传感器”，确认出现 MPU6050。线路为 SDA GPIO8、SCL GPIO9、3V3 与共地。
5. 如需电脑 Claude 或联网参考，运行 `LabCapsule-Studio-1.3.0.exe`，在 Studio 设置中开启手机桥。在 APK 的“设置 → 电脑与 Claude 权限”填写 Studio 地址和六位一次性配对码。

## 二、直接开始一次真实实验

在首页输入，例如：

```text
马上帮我测试 10 秒的桌面震动情况。
```

随后会按顺序发生：

1. APK 显示“AI 正在分析”，此时没有向设备发送 START。
2. 在线 AI 返回严格实验 JSON：实验名、`sensor_ids`、`sample_rate_hz`、`duration_seconds`、分析方法、参考模式、参数理由和安全说明。
3. APK 本地重新校验。当前真实执行驱动只接受 `mpu6050`，采样率 10–500 Hz，AI 实验时长 1–1800 秒，预计样本不超过 500000。
4. 若 AI 认为需要外部信息，先执行电脑 Claude 推理或联网参考。步骤失败时不会启动实验。
5. APK 重新扫描 I²C；只有 15 秒内的新鲜扫描明确发现 MPU6050 才继续。
6. APK 向当前有效通道发送 START。HTTP 必须返回 `ok=true`；BLE 必须成功写入并由固件接受。
7. 设备接受后，APK 才记录开始时间、创建历史项并切到数据页。
8. BLE 下实时接收六轴点并写 CSV；局域网模式由设备离线分区缓存，结束后自动同步到 APK。
9. 完成后 APK 计算 RMS、绝对峰值、FFT 和主频，再把真实结果交给 AI 解释，不允许 AI 编造测量值。

## 三、查看实时状态与终止

数据页顶部显示：

```text
采集中 · 已用时间 / 计划时间 · 当前样本 / 预计样本
```

进度条每 250 ms 更新。点击“终止实验”会发送 `ABORT`：

- 规划阶段终止：直接取消，不发送 START。
- BLE 采集中终止：停止后保存已经收到的 CSV 点。
- 局域网采集中终止：停止设备记录，然后同步终止前的离线数据。
- 历史记录的 `outcome` 为 `aborted`，不会冒充正常完成。

实体设备上的 BACK/ABORT 按键仍可终止固件实验。若 BLE 中途断开，已有数据按中断结果保留；没有收到任何点则明确显示实验异常。

## 四、AI 如何选择参考方式

- `none`：普通桌面震动、运动、姿态或冲击采集，不依赖外部事实。
- `computer_claude`：需要复杂推理，但不需要最新网页资料。Claude 禁用所有工具，只读取 APK 经配对提供的有界状态上下文。
- `computer_web`：问题依赖当前标准、材料参数、产品规格或外部事实。Studio 只为本次 Claude 子进程开放 WebSearch/WebFetch；禁止 Bash、Read、Write、Edit、MCP、Chrome 自动化和本机设备操作。

手机桥默认关闭，Token 仅在六位码配对后生成，电脑只保存 Token 的 SHA-256。授权范围为 `computer.status`、`labcapsule.context`、`claude.delegate`、`reference.web`。

## 五、离线和回退行为

- AI 未配置、手机无网络或 AI 请求失败时，APK 会明确说明使用“本地安全模板”。
- 只有问题明确属于震动、运动、冲击、姿态、加速度、陀螺仪或桌面振动时，本地模板才允许规划 MPU6050。
- 温度、声音、光照等非运动问题不会被错误地交给 MPU6050；APK 会要求补充条件或先接入对应传感器驱动。
- 回退协议仍必须经过参数校验、I²C 预检和真实 START 确认。

## 六、异常检查

| 现象 | 实际含义 | 处理 |
| --- | --- | --- |
| AI 规划被安全校验拦截 | AI 给出不支持的传感器或越界参数 | 改写目标，或先开发对应传感器驱动 |
| MPU6050 预检失败 | 新鲜 I²C 扫描未发现芯片 | 检查 GPIO8/9、3V3、GND 与地址 |
| 设备未接受 START | 固件处于冲突状态、传感器异常或链路失败 | 查看设备状态，终止旧实验后重试 |
| 等待设备完成回包 | 计划时间已到但数据仍在收尾 | 保持连接，必要时点击终止 |
| 设备报告传感器采集错误 | 采集中 MPU6050 读取失败 | 保留已有数据，检查供电和接线 |
| `staConnected=false` | ESP32 未连接外部 2.4 GHz Wi-Fi | 纯 5 GHz 环境直接使用 BLE |

## 七、当前边界

V1.3 的规划协议已经支持传感器 ID 数组和扩展注册表，但固件真实采样任务目前只实现 MPU6050。新增传感器必须同时实现固件驱动、能力描述、数据帧/存储格式、APK 解析与分析器，再加入执行白名单；仅在 I²C 列表中发现地址，不等于已经具备可执行实验驱动。

ST7789 是只写 SPI，APK 的 240×320 监看是同构状态渲染，不是从面板读取像素。局域网 HTTP 当前适用于受信任 LAN；跨互联网远程连接仍应通过经过认证的中继服务，不应直接暴露设备 HTTP 端口。
