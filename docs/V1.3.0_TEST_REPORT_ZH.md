## COM8 实机

设备：ESP32-S3 rev 0.2、8 MiB PSRAM、MAC `00:00:00:00:00:00`、稳定设备 ID `lc-000000000000`。

1. 烧录：COM8 以 460800 baud 写入 bootloader、分区表、OTA 初始数据和应用；每个区域 SHA 校验通过。没有擦除 NVS、wallpaper、offline 分区。
2. 连接：最终固件 `PING` 返回 `PONG,LABCAPSULE,1.3.0-alpha,DEVICE=lc-000000000000`。
3. 传感器：`SENSORS` 返回 `COUNT=1,MPU=OK,ADDRESS=0x68,RESULT=ESP_OK`。
4. 完整实验：`START,50,2` 返回 START 确认；共收到 100 点，最后返回 `OK,COMPLETE,SAMPLES=100`。
5. 终止实验：`START,50,5` 后在第 20 点发送 ABORT，返回 `OK,ABORT,SAMPLES=20`。
6. 静止样本示例：首点 `AX=0.0056 g, AY=-0.0022 g, AZ=1.0267 g`；末点时间戳约 1.990160 秒。
7. 状态恢复：先前遗留的 `ERROR` 状态在真实 MPU 读数和重新挂载检查通过后自动恢复为 `READY`，不再只依赖发现缓存。
8. 动画并发：实验期间本地 GIF 静默暂停解码/刷新，实验结束后恢复为 `OK,GIF,PLAY,FPS=8,BYTES=179028`，未再出现伪 `ERR,GIF,PLAYBACK`。

首次实测暴露了采样第 3 点可能出现 `ESP_ERR_INVALID_STATE` 的 I²C 竞争。修复内容为 MPU 与传感器扫描共享总线互斥、实验期间禁止主动扫描、单次读取重试、有限句柄恢复，以及最终失败时封存离线会话。重新编译和烧录后的 100 点完整实验不再复现。

启动日志中的 `WHO_AM_I=0x70` 表明当前模块可能是 MPU6500 兼容器件，而不是标准 ID 为 0x68 的原版 MPU6050；当前固件按兼容寄存器和已配置量程成功读取。若用于定量实验，仍建议执行六轴标定并确认具体芯片型号。
